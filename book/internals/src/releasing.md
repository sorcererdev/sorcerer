# Releasing

A release is a tag `v<version>` on main; everything after the tag is GitHub Actions. All four
crates and the VS Code extension carry the workspace's one version (`Cargo.toml`,
`[workspace.package] version`).

The files:

- **`dist-workspace.toml`**: cargo-dist's settings (`dist` 0.34.0). Five targets
  (`aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`,
  `aarch64-unknown-linux-gnu`, `x86_64-pc-windows-msvc`), the shell and PowerShell
  installers (`sorcerer-scry-installer.sh`, `sorcerer-scry-installer.ps1`, which put `scry` in
  `~/.local/bin`), archives `sorcerer-scry-<target>.tar.gz` (`.zip` on Windows) each with a
  `.sha256`, no self-updater. Only `sorcerer-scry` is a program to release; the library crates
  set `[package.metadata.dist] dist = false`. The archives carry `LICENSE`, `NOTICE` and
  `README.md`. The targets and archive names are a contract with the VS Code extension, which
  downloads `v<its version>/sorcerer-<product>-<target>` (`editors/vscode/scry/src/download.ts`,
  `targetFor` and `assetFor(product, target)`, the same file in `editors/vscode/conjure/`): change
  them together.
- **`.github/workflows/release.yml`**: generated by `dist generate` from that file; never
  edited by hand. On a tag it plans, builds `scry` on each target's runner, runs the custom
  jobs below, and publishes the GitHub release with every file. dist 0.34.0 writes a custom
  job as `uses: $/.github/workflows/<job>.yml`, which GitHub refuses, so
  **`scripts/release-workflow`** runs `dist generate` and makes it `./`;
  `dist-workspace.toml` sets `allow-dirty = ["ci"]` so dist accepts the patched file. CI runs
  `scripts/release-workflow --check` (the file is what the script makes) and `dist plan`.
  After changing `dist-workspace.toml`, run `scripts/release-workflow` and commit the result.
- **`.github/workflows/build-grammars.yml`**: dist's `global-artifacts-jobs`. On each of
  dist's own runners (`ubuntu-22.04`, `ubuntu-22.04-arm`, `macos-15`, `macos-15-intel`,
  `windows-2022`, so the grammars need no newer glibc than `scry`; macOS builds for 11.0, or
  10.12 on Intel) it runs `cargo run --release -p sorcerer-core --example build-grammars --
  grammars` and uploads the libraries and their `.sha256` files as `artifacts-grammars-*`,
  which the release attaches beside the binaries: ten files for two languages. The release is
  not published unless every one built (`fail-fast: false`, so every runner still reports).
  When one fails: re-run the failed job from the Actions page if it looks flaky; otherwise fix
  it on main, delete the tag (`git push --delete origin v<version>`, `git tag -d
  v<version>`), and tag the same version again on the fixed commit. Nothing was published, so
  re-tagging is safe. This is where `GrammarCache::user` downloads from
  ([The core](core.md), Grammars).
- **`.github/workflows/publish-crates.yml`**: dist's `post-announce-jobs`. After the release
  is announced, `cargo publish --workspace` with the `CARGO_REGISTRY_TOKEN` secret publishes
  `sorcerer-core`, `sorcerer-lsp`, `sorcerer-models` and `sorcerer-scry` in dependency order.
  A missing token fails this job alone; the release stands. If it fails after some crates are
  up, re-run it; should cargo refuse the ones already on crates.io, publish the rest with
  `cargo publish -p <crate>` in the same order. CI's
  `cargo publish --workspace --dry-run` checks the packages build from what they include.
- **`.github/workflows/smoke.yml`**: run by hand after a release (Actions, smoke, with the
  version). On a bare `ubuntu:24.04` container it installs with the README's shell line,
  checks that no `cc` and no `cargo` are there and that `scry --version` is the version, and
  runs `scripts/smoke-review`: the bistro demo with case b01's planted bug, one live review
  through the Anthropic API (secrets `ANTHROPIC_API_KEY`, `JEV_API_KEY`; at most $0.20),
  where doctor's languages row must say `downloaded` and `scry` must exit 1. On
  `windows-latest` it installs with the PowerShell line and runs `scry doctor` on the bistro
  demo, whose languages row must say `downloaded`.

A rehearsal without a tag: `dist plan` lists every file; `dist build --artifacts=local
--target <this machine>` builds this machine's archive in `target/distrib/`.
